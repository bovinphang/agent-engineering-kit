# V0.2 Agent Runtime 方案及安全边界

版本：0.2.0 · 2026-11-17

## 1. 执行模式

AEK 不封装模型 SDK，也不索取模型 Token。`agent-stage`、`agent-review`、`drive` 调用用户本机安装并已认证的 **Codex CLI / Claude Code CLI / Cursor Agent CLI**。标准库 `child_process.spawn` 以参数数组形式启动子进程，不拼接 shell 字符串。兼容性不是跨平台官方认证；CLI 参数可能随上游版本变化。

| Agent | 阶段执行（只读） | 阶段执行（写入） | 审查（不写原项目） | 数据解析 |
|---|---|---|---|---|
| Codex | `codex exec --json --sandbox read-only --ephemeral` | `--sandbox workspace-write` | 独立新进程 + 临时 worktree | JSONL `item.completed/turn.completed` |
| Claude Code | `claude -p --output-format json --permission-mode plan` | `--permission-mode acceptEdits --disallowedTools Bash` | 独立新进程 + 临时 worktree | JSON envelope `result` |
| Cursor | `cursor-agent -p --output-format json` | 增加 `--force`，风险最高 | 独立新进程 + 临时 worktree | JSON envelope `result` |

来源：[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)、[Claude CLI 官方参数](https://docs.anthropic.com/en/docs/claude-code/cli-usage)、[Cursor 无头 CLI](https://docs.cursor.com/en/cli/headless)。运行实际 `agent-check` 和版本确认后方可视作本机兼容。

## 2. 自动阶段驱动（aek drive）

```
start
  -> 根据 state.json 选择阶段
  -> 若存在未确认 DEC，则 PAUSED
  -> requirements/spec/design/plan -> Agent CLI -> aek advance 机器门禁
  -> implement -> Agent CLI -> Git 范围审计 -> [人工提交或授权自动提交] -> aek advance
  -> verify -> 实际执行 task-contract 命令 -> 检查签名证据
       -> FAIL -> [最多 2 次] Agent 修复 -> 任务路径审计 -> 新提交 -> 重新执行验证
  -> review -> 新临时 Git worktree -> 全新 Agent 子进程 -> JSON 审查 -> 导入审查记录
  -> deliver -> 发布前材料 + 受监管人工审批（仅本地声明，不取代企业身份审批）
  -> learn -> 经验文档 -> DONE
```

默认 `--max-fix-attempts 2`，允许范围 0–5；没有修复、越过契约、测试仍不通过时停下，不无限重试。已通过的阶段由项目状态恢复。若当前项目在 `main/master/develop/release/production` 等分支，`--auto-commit` 会拒绝自动提交。

### 自动提交约束

- 仅在 Git 功能分支启用，并且必须显式设置 `--auto-commit`。
- 实现前先提交已经确认的 `docs/`；实现后仅提交单一任务契约 `allowed_paths` 指定的修改。
- **V0.2 仅支持单任务的自动提交**。多任务 DAG 仍可手动开发/提交，但不保证跨任务自动提交的正确归因；若需全自动多任务应先实现任务级 worktree/commit 关联。
- 自动提交只代表保存工作状态；**不代表代码已经通过测试、审查或发布**。

## 3. 问答与门禁

Agent 可返回 `{"summary":"...","questions":[...]}`，由监督层导入 DEC（必须包含问题、2–4 个选项和原因）。没有用户明确选择的阻塞问题无法推进。`aek answer DEC-ID A` 保存用户选择。阶段通过仍依赖 `aek advance`，不能凭 Agent 的一句 PASS 跳过门禁。

## 4. 审查隔离

`agent-review` 从待审 Git HEAD 建立**新的临时 detached worktree**，并使用新的 CLI 进程/会话与生成的 context ID。向 Reviewer 提供 Spec、任务契约、最后提交的代码差异（截取最大 64 KB）和本地测试证据摘要。模型必须返回按任务 ID 标识的 JSON finding 与 verdict。出现未关闭 High/Critical、JSON 非法、Reviewer 改动临时 worktree、验证证据过期等情况时直接失败。执行日志保存在 `.ai-engineering/agent-runs/`，默认 Git 忽略。

隔离是**文件工作目录和上下文分离**，不是可信的 OS 沙箱。子进程可能获得当前用户账户可访问的凭证、网络和其他文件。`reviewer_id` 也不是远程身份加密认证；金融/生产场景应使用独立受控 CI、人工授权、云端审查身份记录，以及更严格的容器/沙箱。

## 5. 仍未完成的能力

- 三款商业 Agent 真实宿主的模型调用、安装、登录状态及端到端成功率尚未验证（本次执行环境没有这些 CLI）。
- 多任务 worktree 并行编排、独立 reviewer 可信身份签名、PR/CI 的服务端规则验证、UI 决策表单、CI 安全凭证注入、容器级网络/文件权限隔离未实现。
- Cursor `--force` 可能运行宿主允许的高风险操作；请先在临时测试仓库执行，**不要在生产代码库上盲目开启自动写入**。
- 最后一个实现提交的 diff 只是 Reviewer 输入之一，不代表已覆盖完整分支历史；Reviewer 还必须阅读仓库关键源码和全部任务。
- 当前 HMAC 只能提供本地误篡改检测，不证明恶意本地 Agent 无法伪造报告。
