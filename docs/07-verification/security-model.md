# 本地工程内核安全模型与限制

## 信任边界

- **可信约束**：工程 CLI 通过严格数据结构、Git、本地 Node 执行器及路径校验进行客观检查。
- **非可信输入**：用户复制的需求、外部网页、项目源码注释、自动生成的 Skill/Prompt 建议、任务合同内任意命令。
- **必须有外部安全边界的操作**：生产部署、资金处理、跨租户数据访问、数据库迁移、出站发送、受保护分支合并。不能仅凭自填 `--actor human` 获得安全授权。

## 当前已实现的检查

1. 安装器不覆盖现有文件；发现软链接目标拒绝写入；只删除清单中未被修改过的文件。
2. 用户关键决定通过 DEC 问题和显式 `aek answer` 记录；防止默认选项自动替代业务授权。
3. Spec 声明的 FR 必须有对应 AC；每条 AC 必须由任务合同覆盖；依赖环会阻断。
4. 修改路径合同通过规范化/防穿越与 glob 匹配审计；提交前仍应检查完整 PR Diff，当前主要校验被验证提交中的文件。
5. `aek verify` 需要 `--allow-exec`，使用 `spawn(argv,{shell:false})` 运行真实命令，记录退出码、输出摘要和有效 HMAC。工作区源码必须已提交；签名证据随需求/合同/被验证的代码源树变化失效。
6. 独立审查导入必须声明与实现者不同的 ID 和上下文，并在 Critical/High 未关闭时拒绝通过。
7. regulated 项目本地交付需要标记审批，`release-ready` 不提供生产部署或合并能力。

## V0.1 未实现的高安全要求

- HMAC 密钥存放在同一个本地项目运行时目录：任何可读该密钥、可修改源码的进程都可能伪造本地签名。要实现可信 attestation，需要把执行者密钥、工作流与仓库写权限隔离，并以 CI 受保护环境的签名与状态检查作为合并门禁。
- Reviewer 的身份来自导入 JSON，不是可独立证明的机器身份，必须有外部平台可核验的审查记录。
- 没有可信权限代理或 OS 沙箱，任务合同中的程序仍能在进程权限范围内访问文件、执行网络请求；`--allow-exec` 不意味着所有命令自动安全。
- 未实现全仓 SAST、SCA、secret scanning、集成测试和 E2E 的统一自动配置；这些应由宿主项目 CI/Profile 提供。
- 未强制操作系统级路径沙箱（可防简单路径穿越，不保证阻止恶意进程或 Git hooks 的所有副作用）。
- 未覆盖可信人类授权 UI，CI 受保护环境与管理平台审批需要后续集成。

**银行及高风险项目：将本包用作开发指导与本地辅助，不允许凭其单独替代企业 CI 审批、DLP、安全审计或生产变更流程。**
