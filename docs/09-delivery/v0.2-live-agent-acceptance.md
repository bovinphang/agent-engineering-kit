# V0.2 真实 Agent 宿主验收操作手册（Windows PowerShell）

**状态：待在已安装并登录的 Codex、Claude Code、Cursor 宿主执行。** 本文件提供可复现命令，不包含伪造的执行结果。请在 **临时、无敏感数据的新仓库** 运行以下流程，再在真实项目试点。

## 1. 检查宿主和版本

```powershell
$AEK = 'D:\tools\agent-engineering-kit' # 替换为你解压 V0.2 源码的目录
node --version # 必须 Node 22+
git --version
node "$AEK\bin\ai-engineering.mjs" agent-check codex
node "$AEK\bin\ai-engineering.mjs" agent-check claude
node "$AEK\bin\ai-engineering.mjs" agent-check cursor
```

`available: false` 是**未安装或 PATH 未配置**，不是通过。Codex 和 Claude Code 建议采用两个独立 CLI 身份/上下文执行实现与审查；仅使用一种模型的新会话可做流程验证，但不等同于异构独立审查。

## 2. 创建隔离的验证仓库

```powershell
$Repo = Join-Path $env:TEMP "aek-live-v02-$(Get-Date -Format 'yyyyMMddHHmmss')"
New-Item -ItemType Directory -Path $Repo | Out-Null
Set-Location $Repo

git init -b feat/aek-host-smoke
# 需要系统已有 Git user.name/user.email；否则先进行本地 Git 身份配置。
Set-Content -Path '.gitignore' -Value '.ai-engineering/' -Encoding utf8
Set-Content -Path 'app.js' -Value 'export const greet = (name) => `Hello, ${name}`;' -Encoding utf8
Set-Content -Path 'app.test.mjs' -Value "import {test} from 'node:test'; import {strict as assert} from 'node:assert'; import {greet} from './app.js'; test('greet',()=>assert.equal(greet('A'),'Hello, A'));" -Encoding utf8
git add .gitignore app.js app.test.mjs
git commit -m 'test: baseline for AEK real agent smoke'

node "$AEK\bin\ai-engineering.mjs" init --project $Repo --kind feature
node "$AEK\bin\ai-engineering.mjs" install codex --project $Repo --dry-run
node "$AEK\bin\ai-engineering.mjs" install codex --project $Repo
node "$AEK\bin\ai-engineering.mjs" start '在现有 Node.js 小项目中新增 greet(name, formal=false) 函数：formal=true 时返回 Good morning, NAME；默认行为不变；新增 node:test 正反例；不安装依赖、不调用网络、不修改契约外文件。' --project $Repo
```

## 3. 直接执行端到端流程（需已授权 Agent CLI）

```powershell
$cmd = "$AEK\bin\ai-engineering.mjs"
node $cmd drive --project $Repo --agent codex --reviewer claude --allow-agent-exec --allow-writes --allow-tests --auto-commit --max-fix-attempts 2
$exit = $LASTEXITCODE
node $cmd status --project $Repo
```

结果字段：`complete` 表示九阶段的**本地门禁**全部通过；`paused` 表示等待业务决定、代码提交、权限或修复；`failed` 表示 Agent 子进程失败或协议异常。`paused` 返回退出码 2，`failed` 返回退出码 1。不可将生成文本中的“测试通过”当作执行证据。

如果 `paused` 因 DEC 问题而停止：

```powershell
node $cmd questions --project $Repo
node $cmd answer DEC-001 A --project $Repo  # 实际 ID 和选项以 questions 输出为准
node $cmd drive --project $Repo --agent codex --reviewer claude --allow-agent-exec --allow-writes --allow-tests --auto-commit
```

如果是 `regulated` 的交付，则必须由有权限的负责人进行审批并在企业流程留痕。`aek approve deliver --actor human` 仅保存本地声明，不具备企业 SSO 签名能力。

## 4. 逐个 Agent 对照实测

- **Codex**：`agent-stage codex --allow-agent-exec --allow-writes`，验 `item.completed` 与 `turn.completed`；评估沙箱 workspace-write 是否实际限制到仓库。
- **Claude Code**：`agent-stage claude --allow-agent-exec --allow-writes`，验 `--output-format json`、权限提示、Write/Edit 能否实际创建文件。
- **Cursor**：仅在临时仓库运行 `agent-stage cursor --allow-agent-exec --allow-writes`；特别检查 `--force` 可能允许 Bash 与高权限写入；不建议先在敏感企业仓库运行。
- **Reviewer**：`agent-review claude --allow-agent-exec`，检查临时 worktree 和独立日志；不能接受缺少具体审查内容的空洞 PASS。

## 5. 每项宿主验收需要保存的证据

记录 Agent 版本、模型/认证方式（不要存密钥）、项目目标、Run ID、每个 stage 的启动与结束时间、实际修改文件/提交 SHA、真实测试命令退出码、审查原始 JSON、耗时/重试次数/费用（有能力则记录）、人工 DEC 问答、最终状态和缺陷。

推荐把验收结论写入独立 `docs/09-delivery/host-acceptance-YYYYMMDD.md`；不得直接修改 `.ai-engineering/state.json` 伪造结果。两种试点都通过后再将兼容性矩阵 S3 更新为 `PASS`。

## 6. 已知限制与备选

- 若任一 CLI 不存在，不存在自动模型调用的合理替代；请先安装并完成认证。
- 多任务自动提交尚未实现：遇到该停点，可按任务契约拆分提交，并通过 `aek verify --allow-exec` 做验证。
- GitHub PR/CI 受保护分支规则与真实监管审批不由本地 CLI 代替。
- 不允许自动发布/外发/删库。该验收流程只作用于本地临时 Git 仓库。
