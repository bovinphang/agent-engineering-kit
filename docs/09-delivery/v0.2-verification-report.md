4. 真实 Git 临时 worktree 审查、非法 JSON/未关闭严重问题/只读 checkout 被修改的拒绝行为。
5. 真正执行 Node 模块导入测试、自动提交、测试失败自动修复、重跑验证、到第九阶段完成的全流程**模拟模型**演练。
6. 保护 `main`、阻止未修复/未修改的无限循环、隐藏模型会话日志、同 SHA 失败后成功证据优先顺序。

## 结论

**本地工程内核的 E2E 调度可复现，尚不能判定真实商业 Agent 的成功率与任务质量。** “已验证”是对子进程调用链、协议校验、状态门禁和测试证据的验证，而不是对大模型工程能力的背书。外部宿主的模型调用、权限行为、Skills 触发、费用和真实项目交付验收仍需执行 `v0.2-live-agent-acceptance.md`。

## 当前约束

- 自动提交仅支持单个任务契约及非受保护功能分支；多个任务涉及的代码修改可能互相干扰，需要任务级提交策略。
- Cursor 强制写入、Claude 自动授权及 Codex 沙箱限制属于**不同信任模型**，不能等同于一个 OS 级沙箱。
- 提交到 Git 不等于业务需求正确；还需要覆盖充分的测试、独立人工判断、真实功能验收。
- 当前审查记录和本地 HMAC 未达到高安全生产系统的可信审计要求。
